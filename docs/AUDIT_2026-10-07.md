## Understanding and architecture

Prentice is an orchestration, evidence and learning workspace around separately installed coding agents. The main product loop is Build → Understand → Explain-back → Continue, with Debug for recorded failures. It is not the coding agent or an editable cloud IDE.

Hosted flow: Next browser → Supabase-authenticated Prentice cloud → in-memory WebSocket relay → outbound local connector → local filesystem/Git and installed agent. Providers perform local repository operations and use vendor inference. The connector stores tasks, prompts, events, evidence, conversations and learning state in local SQLite. Cloud Postgres stores device/account/project metadata, pairing codes and hashed bearer credentials; no code path intentionally persists full task frames or learning payloads there. Relay frames can contain repository text and are visible to the cloud while being forwarded; end-to-end encryption is explicitly outside the current architecture.

Learning flow: connector produces an evidence summary → device-authenticated cloud endpoint → Groq with the cloud-owned key → explanation/question/judgment → local learning record. Failure output is limited to 4,000 characters/80 lines locally and 1,500 characters per command in the Learning AI summary. Agent statements have separate labels and caps. Commands, file lists and other summary fields do not have a total connector-side summary budget.

Development uses authenticated loopback HTTP/SSE for the workspace and a loopback cloud with a per-run Learning AI token. Packaged mode bundles the connector, parser modules and a pinned Node runtime; agents are discovered separately. Mac packaging has optional signing/notarization steps. Windows packaging currently produces an unsigned ZIP and batch launcher.

Conversations are local project records, with per-conversation provider threads, shared working trees and an in-process project lock. Codex Continue resumes the recorded thread. Claude and Cursor continuation is explicitly unavailable. Normal turn evidence compares before/after worktree content, including already-dirty files.

## Priority findings

### 1. Failure-output redaction leaks common credential forms — high

`packages/domain/src/output.ts:8` and `apps/connector/src/learning.ts:225`.

A direct reproduction left all of these dummy values intact: `Authorization: Bearer audit_dummy_credential`, `GROQ_API_KEY="audit fake value with spaces"`, and a credential-bearing `DATABASE_URL`. Regexes cover several token prefixes and bare key names, but miss these forms. Stored output can reach the browser/cloud/Groq. Raw command strings, session error text and bounded agent statements also bypass this output redactor. A size cap does not establish secret safety or failure relevance.

Recommendation: consistent credential scrubbing across outbound/stored evidence fields, with explicit tests for headers, environment assignments, quoted/multiline secrets and connection URLs. Do not broaden what is collected.

### 2. Workspace file access follows symlinks outside the repository — high

`apps/connector/src/workspace.ts:19` and `:58`.

The containment check is lexical. `stat` and `readFile` follow symlinks. A temporary repository containing `linked.txt` pointing to a file outside it successfully returned that outside file's contents. Nested symlink directories have the same issue. The tree hides symlink entries, but callers can still request a path directly.

Recommendation: enforce canonical filesystem containment when opening files, including symlink ancestors and race considerations. Preserve the read-only viewer.

### 3. Local pairing page has no origin/CSRF protection — high

`apps/connector/src/pair-surface.ts:26`.

A local stub accepted a form POST with `Origin: https://audit-attacker.invalid`, returned 200 and invoked pairing with the dummy code. The page has no pairing-session nonce, Host/origin enforcement or body limit. A valid code supplied by an attacker would pair an unpaired connector to that code's account if the request reaches localhost. Browser restrictions may affect attack delivery; no browser exploit was performed. The application boundary itself does not reject it.

Recommendation: bind pairing submission to the local pairing interaction, validate origin/host and bound request bodies. Keep the established code-entry workflow.

### 4. Relay authorization and connector replacement are incomplete — high

`apps/cloud/src/relay.ts:122`, `:134`, `:165` and `:173`.

Browser credentials are checked only during the initial auth frame. A fake-store reproduction authenticated once, subsequently made auth refuse the session, and still forwarded a workspace request without another check. Updating the browser's access token only affects a future reconnect. There is no socket-expiry deadline or renewal protocol. An already-open socket can outlive its initial authorization.

Authenticating another connector for the same device replaces the map entry but leaves the old socket alive. A reproduction showed the superseded connector's response reaching the browser, and device revocation failing to close that superseded socket. Forwarding does not verify that a connector is still the current socket. Responses are broadcast to every browser on that device, and task subscriptions are device-wide: one tab's unwatch can stop another tab's stream. Pending requests have no relay-side deadline, although browser promises do time out.

Recommendation: close/reject superseded connector sockets, enforce ongoing browser authorization, route responses to the requesting browser, and account for multiple watchers. Preserve transient-error/revocation separation. Strict immediate account-sign-out invalidation is a separate policy choice; Supabase explains that access-token revocation needs additional session checks in its [session documentation](https://supabase.com/docs/guides/auth/sessions).

Also, `CloudStore.userForSession` collapses all Supabase auth errors into an invalid session. A temporary auth-service response can therefore trigger SESSION_EXPIRED instead of TEMPORARY even though mock tests cover thrown store errors.

### 5. “Agent stated never becomes Observed” is not enforced — high product correctness

`apps/connector/src/learning.ts:57` and `:89`.

A direct reproduction supplied only the agent claim “The change prevents SQL injection.” and asked the parser to accept that same sentence as observed. It remained in Observed with no observed evidence. The guard checks quoted spans, numbers and numeric comparisons; unquoted prose and invented claims pass. The legacy free-text fallback can also classify the whole explanation as observed. Learning prose does not use the domain's citation validator. That validator itself checks citation existence, not whether an Observed claim cites only observed evidence.

Recommendation: choose a concrete grounding contract before changing learning behavior. Options are conservative, deterministically generated observed facts with model prose treated as interpretation; or structured claims tied to typed evidence with unsupported claims rejected. A model instruction and token heuristic cannot guarantee the stated principle.

### 6. Child process lifetime does not guarantee crash safety — high

`apps/connector/src/agent-process.ts:18` and `:27`; `apps/connector/src/session.ts:578`.

Non-detached children do not automatically die with the parent. Using the actual `runJsonLines` helper and a harmless dummy child, a parent exited and the child subsequently wrote a temporary marker. This disproves the helper comment's general guarantee. It does not prove that a particular vendor CLI survives every connector crash. Interrupt targets the immediate child, without a process-tree containment mechanism; Windows behavior is not verified. Recovery marks stale task rows interrupted based on absence from the in-memory running map, not proof that all child work stopped.

Recommendation: verify and enforce process lifetime containment on both operating systems before promising that a connector crash stops edits or allowing a recovered run to overlap surviving work.

### 7. Setup/process failures can still appear in Debug — medium

`packages/domain/src/debug.ts:16`, `packages/domain/src/activity.ts:49`, `packages/domain/src/normalizers.ts:76` and `apps/connector/src/providers.ts:303`.

Dummy reproductions show both a generic provider process crash and a command with unknown exit status becoming Debug entries. The exclusion list misses PROVIDER_UNAVAILABLE, PROVIDER_ERROR and other non-code failures. Codex `turn.failed` always becomes PROVIDER_ERROR, including authentication errors delivered as stream events; only thrown exceptions receive auth classification. These paths can present setup failures as code defects and fail to invalidate the auth cache.

Recommendation: classify provider/setup failures before Debug, and require recorded command/test/tool failure evidence for a code-defect entry. Unknown exit status is not a demonstrated nonzero exit.

### 8. Task attribution falls back to a misleading baseline — medium

`apps/connector/src/session.ts:333` and `:444`.

When either snapshot fails, the code silently falls back to the diff against the original commit. That can attribute existing dirty/untracked changes to the current task, contradicting the task-specific evidence rule. Interrupted runs return before constructing Git/Understand evidence, so their partial edits remain on disk without an equivalent teaching artifact.

Recommendation: mark attribution unavailable when a baseline cannot be established. Decide separately whether interrupted turns should receive partial evidence/Understand.

### 9. Approved connection/release details are incomplete — medium

- **Prentice account Sign Out:** implemented separately; `product-shell.tsx:143` calls Supabase signOut and does not call vendor logout.
- **Agent connection controls:** `accounts.ts:111` still invokes Codex/Cursor `logout`; the Agents menu calls it “Sign Out” and explicitly warns of computer-wide effects. Local Disconnect/Reconnect semantics have not been implemented.
- **Computer name:** `pair.ts:8` sends no name; `CloudStore.pairDevice` defaults to “This computer.” Displaying a saved name in the UI does not populate it.
- **Claude authentication:** correctly outside Prentice; no automatic Claude login/logout path. Some status parsing still assumes readiness from an unrecognized exit-0 status response.
- **Windows installer:** absent. The package is an unsigned ZIP containing a `.cmd` self-copy launcher. `PRENTICE_WIN_SIGN_COMMAND` appears only in a comment, not executable signing code.
- **Release gate:** checks HTTPS/non-localhost addresses, but does not require signing/notarization or distribution readiness. Windows can be labeled release while unsigned. Mac signing and notarization have code paths, not freshly verified artifacts.

## Recommended order and decisions

1. Fix privacy, filesystem and pairing boundaries; relay stale-socket/authorization handling; provider failure classification; misleading attribution fallback. These follow the existing decisions and need focused regression coverage.
2. Establish reliable child lifetime containment and verify real crash/stop behavior on Mac and Windows.
3. Implement approved computer naming and clarify the local connection controls; remove misleading capability/documentation claims.
4. Restore a reachable test Supabase configuration and rerun the seven blocked tests. Make web typecheck work in a clean checkout.
5. Verify authenticated providers and signed installers outside the repository, then validate a deployed cloud/download/install/reconnect flow.

Decisions requiring input before implementation:

- Scope and persistence of **Disconnect/Reconnect**: disabling a provider for the connector/device, repository or current session while preserving its global vendor login.
- The exact **learning grounding contract**: deterministic observed facts with separately labeled model interpretation versus model-generated claims that must reference typed evidence.
- The **Windows installer format/toolchain** and available release-signing identities/infrastructure; the requirement for a proper installer is already approved.
- Whether **interrupted turns receive partial Understand evidence**; current behavior omits it.
- Whether Prentice account **Sign Out must immediately invalidate other live browser sockets**, beyond preventing expired credentials from keeping a socket authorized.

No provider migration, architecture redesign, added infrastructure or visual redesign is recommended by this audit.
